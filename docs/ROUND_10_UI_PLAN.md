## 3. 每轮范围与可信数据（先实现）

“任务”在侧栏代表一个会话；“本轮”代表一次用户提交至处理终止；结果卡里的“任务项”是这一轮的工作项，三者不要混为一谈。

现有问答续接可能生成新turnId。新增稳定logicalRoundId：原用户提交与其提问/审批等待、用户回答后的继续属于同一展示轮，执行attempt单独记录。用户显式发起新消息是新轮。恢复中断保留来源关系；后台验证模型、自动命名等不能算用户轮次或重复工具步骤。

拟议持久数据（名称可按仓库惯例调整）：
- RoundSummary v1：sessionId、logicalRoundId、attemptIds、起止时间、状态、文件变更引用、任务项、usage完整性。
- RoundFileChange：稳定fileId、相对路径/旧路径、变化类型、before/after快照引用与哈希、增删行数、来源执行ID、可信度/不可用原因。
- RoundTaskItem：id、标题、状态、来源plan/tool/attempt ID、简短结果、可展开的证据引用。
- RequestUsage：唯一requestId、session/round/attempt、角色、provider标识/修订、modelId、输入/输出/缓存token、是否最终记录、数据来源和完整性。

使用附加的版本化只读投影/摘要记录，不破坏现有恢复journal。当前dispatch-journal只保存最近dispatch，不能充当所有历史轮的唯一数据源。完成事件仅在摘要写入完成后广播；写入失败保留对话并显示“摘要暂不可用”，不能悄悄生成空的成功卡。旧会话缺数据展示“历史数据未记录”，不倒推精确耗时/用量。

## 4. 修改文件卡与只读阅读（图2–4）

每轮正常结束、失败或中断后，在黑塔回复/终止说明下方显示“本轮修改N个文件”和总+/-行数。模型可以解释变更用途，但文件成员、数字和diff由执行记录及快照生成。纯聊天显示轻量“本轮未修改文件”，不空占大卡片。

- 默认列出路径、文件图标、类型标识与+/-；长列表先显示约6项，可展开/收起。新增、修改、删除、重命名分别标记。
- 比较本轮开始前与结束后的内容，不用工作区相对HEAD的全部dirty diff冒充本轮成果。保留用户已有未提交修改作为基线。
- 写文件工具：首次触达前记录before，完成后记录after，多次修改同一文件合并为本轮净变化；改回原样不计净修改，可在明细说明曾操作。
- 命令也可能修改文件：实施时先验证现有工具/仓库快照能力。采用受范围和大小上限约束的前后快照，覆盖Git及非Git项目、新建未跟踪文件；不为审阅执行git reset/stash/add或创建影响用户索引的动作。工具记录无法证明来源或外部并发修改时标“期间检测到变化，归属不确定”，不声称全由黑塔修改。不能仅靠文件mtime推断内容。
- 不能完整快照的大文件、二进制、目录外结果、编码不支持、忽略目录等明确标记限制。先定义并测试上限，再实施；不扫描磁盘/依赖目录到卡死，也不静默把未扫描文件计作0变化。
- 快照保存在应用会话数据中，按内容哈希去重；使用已有路径/凭据保护，禁止新审阅入口绕过主进程读取任意路径。限制单文件/单轮存储，达到上限显示原因，不存密钥或应用内部凭据目录。
- 历史卡读取当时冻结diff，不重新读取今天文件来替代过去成果。文件后来删除也能看已保存的历史变化。
- 悬停约350ms弹出只读预览，最大约720×420px且约束视口；移进预览可继续滚动，移出短延时关闭；Esc关闭，点击其他项替换，异步旧请求不能串到新文件。不抢键盘焦点，不阻挡点击。
- 点击文件或键盘Enter打开右侧固定阅读面板；预览消失，面板显示文件路径、本轮编号、+/-、关闭入口。单一面板可切文件，首版不强加多标签系统。
- 阅读复用等宽字体和关键词高亮，增行绿底、删行红底、上下文中性底；支持双侧行号或明确旧/新行号与+/-符号，删除行必须可见。默认统一diff，保留横向滚动；长行不撑坏布局。重命名显示旧→新；二进制等显示元信息和原因，不假装文本diff。
- 首版只读，不附带恢复/回滚/覆盖文件操作。卡片计数、悬停预览与固定面板必须使用同一快照。

## 5. 任务结果与状态用时（图2、5）

每轮正常结束、失败或中断后显示“本轮任务结果”卡，默认可见简短条目及成功/失败数量，可折叠。来源优先现有结构化计划及执行证据；没有计划则按真实工具动作形成简明列表，不为了好看让模型虚构任务。

- 状态至少：成功、失败、未执行/取消、未验证；运行时可记录进行中/等待。未知不是成功，未运行测试必须写未验证。
- 命令exit0代表命令执行成功，不自动等于用户目标或测试结论正确。计划项仅有模型完成声明但无证据时标“待验证/模型报告”，并与工具事实区分。
- 条目名称可由模型简述，但状态不能由自由文本覆盖；能展开定位对应输出/失败原因。一次重试多attempt归到同一任务项，保留失败证据，避免重复算多项成功。
- 回复附近增加“已完成 · 用时6分3秒”式状态行。处理结束但存在失败项：显示“已结束 · 有失败项”，不要整体绿色成功。
- 用时定义为用户提交被主进程接受至本轮终止的实际总时间，包括审批/补充信息等待；运行中每秒更新UI即可，不每秒写盘。等待不是结束，不提前生成最终卡。
- 使用运行时单调时钟累计片段、持久化起止/等待事件；重启恢复不能凭当前时间伪造持续运行时长。不确定区间标记或显示--。底层记录等待时间，首版不新增复杂时间分析图。

## 6. 输入框与仪表盘（图6）

- 输入框下方一行紧凑仪表盘：会话轮数/本轮步骤、可用时的输出速度、任务累计tokens、缓存命中率、当前上下文。窄屏合理换行，详细口径在悬停说明中，不把长技术文案常驻界面。

### 指标定义与占位规则

| 指标 | 口径 | 不足时 |
| --- | --- | --- |
| 轮次 | 当前会话用户发起的逻辑轮数，问答续接不重复计轮 | 旧记录无法可靠归并则-- |
| 步骤 | 当前/最近轮实际派发的工具调用次数，拒绝/未执行单列，不混成成功 | 不把模型token或审批事件计步 |
| 速度 | 有完整输出token和对应生成时长时，输出tokens/生成秒数；多角色合计须标口径 | 不按字符猜，无法确认-- |
| 任务总tokens | 当前侧栏任务会话累计、角色+执行器真实请求的输入+输出；回复旁另显示本轮用量 | 部分缺失不把小计当总量，显示--，可提示已记录部分 |
| 缓存命中率 | 同范围sum(cacheHitInputTokens)/sum(inputTokens)，输入已包含缓存命中部分 | 分母0或任何所需字段未知显示--，不能用逐请求百分比简单平均 |
| 当前上下文 | 当前角色最新有效请求的已用输入上下文/可信模型窗口；执行器可在详情分列 | 已用量或窗口未知显示--，不能把任务累计token当上下文 |

按用户本轮展示策略，优先支持DeepSeek服务经确认可用的字段；OpenAI/Anthropic及未接入统计能力的服务显示--。这是产品展示范围，不声称这些API天然完全不提供usage。协议格式和服务身份必须分开：DeepSeek采用OpenAI/Anthropic格式时，不能只看protocol就隐藏支持的统计；自定义兼容网关不能仅凭模型名或用户Provider昵称假定支持。具体适配时核对官方文档与实际字段，本次不做联网或价格研究。

各指标独立判定：有tokens不代表有缓存率或上下文窗口。真正返回0才能显示0；缺失/null不能转0。缓存命中token已计入输入，不重复相加。增量/最终累计usage按请求ID规范化，去重后汇总，避免重连、重复finished、角色+执行器重复上报。失败请求只有服务实际返回usage才记录；不推测计费。部分混合Provider缺统计时任务总量仍标--，可在详情展示已知小计与来源。

不新增金钱估算、余额仪表或自动API探测。不因为查看仪表盘额外调用模型。

## 9. 用户已确认的扩展（纳入必做）

### 层级与交互

1. 轮级入口复用“已完成/失败/已中断 · 用时…”状态行，展开后查看本轮过程。进行中显示当前状态；正常结束默认收起冗长过程，文件和任务摘要仍可见。失败时保留明显红色失败计数及入口，不自动展开全部长日志。
2. 过程按真实事件顺序列工具动作，可分组为“执行了命令、读取文件、搜索代码、修改文件”等可折叠区块。组标题由实际记录生成，不能未运行先写“已完成分析”。混合结果摘要显示成功/失败数量。
3. 工具行展示类别图标、动作名、简短说明、状态；已结束可带耗时。失败使用红色图标/文字并写明“失败”；取消、拒绝、等待、未知使用独立状态，不全部当失败或成功。
4. 点击有详情的工具行二次展开只读详情，再点收起；没有内容的记录不放假展开箭头。键盘Enter/Space可操作，aria-expanded正确。展开不重新执行工具、不调用模型、不改变审批，不把输出当指令。
5. 工具详情与文件链接使用独立点击区域：点文件名只打开阅读，不同时切换整行折叠。链接沿用延迟悬停预览和点击固定右侧阅读面板；窄窗口采用之前规划的覆盖/下拉阅读形式，不堆出第三套阅读器。
6. 展开状态以会话/轮/工具稳定ID保存于界面状态，至少切面板回来不丢失；新事件到达不重置用户已打开的详情。历史展开不触发自动滚动到底部。

### 各类工具的详情

- 命令：只读命令头（实际shell/程序、工作目录、命令或argv显示、状态、退出码、耗时）及下拉输出框。PowerShell命令标为PowerShell；其他程序不能强行贴PowerShell标签。分区或清晰标记stdout/stderr；stderr有文本不必然失败，退出码/取消/超时和实际工具结果决定状态。无输出显示“无输出”，未采集显示“未记录”，两者不同。
- 输出保持等宽、换行与横向滚动。命令复制只复制显示的命令，不附带执行动作。ANSI控制符安全处理，不解释为HTML。超长日志分段/按需加载并标明截断范围；不能因为截断而漏掉失败摘要。若无法保存全量日志，明确“仅保留部分”，不把“展开更多”做成无效入口。
- 读取：可点击文件名、实际读取行范围/字节范围，以及当次读取内容片段。只有片段时明确标记，不能声称完整文件已保存；点击后阅读该次快照，必要时说明范围不完整。
- 搜索：查询条件、作用范围、匹配数量、支持时带文件和行号的结果；点击定位到可用快照位置。路径来自结构化结果，不把任意输出字符串正则识别后变成可访问任意磁盘的链接。
- 编辑：该次工具调用的diff、新增/删除行数、文件链接，可在行下只读展开。这里的“单次编辑diff”与结束卡“本轮合并净diff”必须标清；同一文件连续三次修改对应三条过程记录，不能每条都展示最终净diff冒充单步结果。
- 其他工具：按实际结构化返回展示简短结果，详情可用格式化只读文本/JSON；不显示凭据、原始授权头或不可展示的内部上下文。不支持详情时直说，不伪造内容。

### 文件版本、持久化与可信边界

工具行引用toolCallId/attemptId/logicalRoundId、fileRef和snapshotRef。链接按用途指向“当次读取/当次修改”版本；结束卡指向“本轮净变化”。面板标题明确来源，不能因为同名文件就混用快照。同文件并发读取/编辑记录按真实序列号关联；无法确认归属显示未知。

新增持久化ToolActivity投影（字段名可按现有结构调整）：稳定调用ID、轮/attempt/角色、工具种类、显示标题、状态、时间、退出/错误摘要、受控详情引用、文件引用、截断标志。由执行器事件和执行journal生成，不能从黑塔最后一句话反推成功。

流式输出按调用ID合并，重连、重开、重复结果事件不新增重复记录；恢复/重试保留各attempt并显示来源，不把历史完成工具计为重新执行。UI读取详情仅经主进程受限接口，以不透明记录ID查找已授权快照/输出，不传任意路径读取。

与第3节事实层一起实施，不能等UI画完才发现日志只保存最新dispatch。避免复制多份巨大输出：详情引用统一存储，摘要只留索引。展示/复制遵守现有密钥遮蔽与路径限制，不新增无限日志采集。

### 思考内容：按API实际提供的可展示内容决定

- 不生成或补写“思考过程”，不从输出语气推断隐藏推理，也不把执行日志命名为模型思考。
- 服务明确返回可供应用展示的思考/推理摘要或公开文本字段，且适配器支持时，才提供相应折叠区。标明“思考摘要”或“服务返回的思考文本”、所属角色与调用；默认收起，空内容不占位。摘要不能冒充完整内部推理。
- 加密/opaque reasoning块、签名、内部缓存或仅用于下一请求续接的私有nativeContext不展示、不转成文本，不因本功能持久化进公开历史；不绕过服务限制提取隐藏内容。其生命周期继续遵守现有提供方实现。
- 返回缺失或此服务不支持展示时省略思考区；不自动开启额外高成本推理参数，不新增API调用来补齐。执行器的公开进度说明仍可正常显示，并与思考区区分。
- 工具记录与思考内容分别存放：没有可展示思考时，工具记录仍完整可读；思考解析失败不能中断执行或覆盖工具失败状态。思考计费token是否包含在output中按服务usage语义处理，不再加一次。

### 追加验收

- 一组工具记录可展开/折叠，单条命令/读取/搜索/编辑详情可独立再展开；无详情无假按钮；键盘和长内容滚动正常。
- stderr非空但exit0、exit非0、超时、取消、审批拒绝、部分输出、结果未知的视觉和文字均准确。
- 文件链接打开正确调用版本；单次编辑与本轮净diff可区分；“完整文件”与删除前快照切换正确；快照缺失有明确提示。
- 失败/中断仍保留已确认修改和任务结果；没有任何完成结果时不误报“部分完成”。
- 旧会话/重启/重连不重复工具行、不重放命令；流式更新不抢用户历史滚动位置。大日志惰性加载不卡住主进程或输入框。
- 可展示思考文本、仅摘要、完全无字段、仅opaque块四种情况分别验证；opaque内容绝不进入UI或公共历史。
