# The Herta：视觉与交互规范

> 当前状态（2026-10-07）：产品已迭代至0.8.4。下文早期轮次状态保留为历史；整体需求核对、证据范围及后续优先级见 [完整目标核对](COMPLETION_AUDIT.md)。

> 文档状态：设计要求；第二轮布局与配置交互已实施，实际覆盖及未测项见 reports/round-2.md。首测环境为 Windows 11 x64，面向 Windows 原生桌面窗口中的 Electron + React 界面；不以网站、浏览器标签页或移动端为交付目标。上游代码复用范围以主实施方案的审计结论为准。用户已选定“大黑塔：深紫与黑金、魔女和星象元素”，角色图优先使用用户提供或已有素材，本轮不生成角色图。

## 1. 设计目标与边界

产品是一款让用户选择项目、发起编码任务、观察执行、审阅修改并控制审批的桌面工作台。角色气质来自冷静、克制、博学的视觉表达；界面清晰程度高于装饰密度。默认语言为简体中文。

- 内容区不铺人物背景，不加入持续旋转的星轨、漂浮粒子、发光边框或大面积金色渐变。
- 默认以纯色、清晰排版、细分隔线建立层级；紫色表示主操作，金色仅用于品牌标识和少量静态点缀。
- 角色插画最多出现在欢迎页的一侧或用户主动打开的角色面板。聊天、代码和审批区域始终保持纯色背景。
- 角色化措辞只用于欢迎语、空态短句；权限、错误、删除和恢复说明采用明确普通语言，不通过角色口吻掩盖风险。
- 无素材时仍可完成完整 MVP：文本品牌、通用图标和少量自绘几何星形即可。这里的几何图形不是生成式角色美术。

正文对比度至少 4.5:1，大字至少 3:1；有意义的图标、焦点和控件边界至少 3:1。`border.subtle` 只承担装饰分隔，不承担控件可识别性。状态同时展示文本与图标，diff 同时显示 `+` / `-`，不能只靠红绿色判断。

字体：界面优先系统 `Segoe UI Variable` / `Segoe UI`、中文回退 `Microsoft YaHei UI`，正文 14 px / 22 px；次要信息 12 px / 18 px；区块标题 16 px / 24 px、字重 600；欢迎页标题 24 px / 32 px。代码字体优先 `Cascadia Code`，回退 `Consolas` / monospace，13 px / 20 px，不要求用户额外下载字体。

间距采用 4、8、12、16、24、32 px；主要面板圆角 10 px，输入和按钮 6 px，禁止每层嵌套都做卡片。常规按钮高 32 px，关键操作与图标按钮点击区域至少 36 × 36 px，输入框最小高 36 px。阴影仅用于弹出层，避免依靠阴影区分普通面板。

## 3. 桌面窗口与布局

首轮优先保留上游已经可用的窗口控制和标题栏；核查拖动、缩放及辅助功能后再统一视觉。若现有实现不可复用，才回退到系统窗口边框，避免为换肤另造一套窗口行为。页面内部所有区域尺寸均为 CSS 逻辑像素，不将缩放比例当成物理像素。

| 区域 | 默认尺寸与规则 |
| --- | --- |
| 初始窗口 | 1360 × 900；最小 960 × 640；不足可用工作区时适配屏幕 |
| 左侧导航 | 宽 240；可拖动至 200–300；可收起为 56 图标栏 |
| 工作区工具条 | 高 48；项目名、任务标题、任务状态、审阅入口 |
| 聊天区 | 占剩余主空间；文本内容最大宽 820，居中；左右边距至少 24 |
| 右侧上下文面板 | 默认关闭；宽 360，可拖动至 300–520；展示文件、变更或任务详情 |
| 输入区 | 与聊天正文同宽；底部内边距 20；输入高度 80–240，超出内部滚动 |
| 底部运行面板 | 默认折叠；展开高 240，可拖动至 160–440；命令输出与日志标签（首版非交互式 PTY 终端） |

三个主要布局状态：

1. **标准窗口（≥1280 宽）**：左侧项目/任务，中央聊天，右侧按需展开上下文。
2. **紧凑窗口（960–1279 宽）**：右侧变更作为主内容替换视图或抽屉；聊天保持至少 520 宽，不能同时挤入三个窄列。日志面板高度不得遮挡输入框。
3. **专注模式**：隐藏导航与上下文，保留任务标题、状态、审批提示和输入；再次触发可恢复原布局。

分隔条支持鼠标和键盘调节；拖动后持久化尺寸，重置布局提供恢复入口。窗口位置与尺寸恢复时检测屏幕边界，防止外接屏拔出后窗口不可见。125%、150%、200% 系统缩放下控件不裁切，设置页和长弹窗可滚动。

## 4. 信息架构与关键页面

### 4.1 导航与项目选择

导航顶端为小型品牌标识与“新任务”，下方为项目列表与当前项目的最近任务，底部为设置。任务行展示标题、状态图标和可选未读标记；完整标题通过可访问名称和悬浮提示获取。项目无路径时使用桌面文件夹选择器，成功后显示名称与可复制的路径；不要让用户手输必填路径。

空工作区显示“打开项目文件夹”主按钮、最近项目列表以及不超过一句的角色气质文案。不预置虚构聊天记录、假的运行进度或假的文件修改。项目不存在时显示明确路径及“重新定位”“从最近列表移除”，移除最近项不得删除磁盘项目。

### 4.2 聊天与任务执行

消息以平面文本流呈现，用户消息使用轻微底色，助手消息不套厚重气泡。代码块可复制，长代码块可展开；工具活动默认显示摘要，展开后才呈现输入、日志与执行结果。状态与真实运行事件绑定，不依靠固定时间生成伪进度。

输入区包含多行编辑框、附加上下文、模型选择（仅列实际可用项）、发送/停止。默认 Enter 发送、Shift+Enter 换行，可在设置反转；中文输入法组合状态下 Enter 不发送。发送后保留草稿恢复能力，运行中允许编辑下一条消息，但后端不支持排队时必须明确显示“任务运行中，完成后发送”，不能静默丢弃。

输出流跟随规则：用户位于底部时自动滚动；向上阅读后停止自动滚动，并显示“回到最新”按钮。新工具事件不抢夺键盘焦点。长消息和长任务使用分页或虚拟化，但保留复制、选择和可访问性。

### 4.3 变更审阅

审阅入口显示真实变更文件数量。文件列表标识新增、修改、删除、重命名及可读取状态；文本 diff 默认统一视图，宽窗口可切换并排视图。二进制、超大文件、编码无法识别分别给出说明，不用空白视图冒充无变更。查看文件路径以项目相对路径为主，提供完整路径。

“批准操作”和“审阅变更”是不同动作：批准表示允许下一步受控执行；审阅表示检查已出现的文件变化，不能让“接受”按钮伪装成尚未实现的应用补丁功能。首版采用只读审阅，不自动回滚；恢复文件、应用分块、提交代码等按钮仅在后端真实支持并有明确语义后加入。

diff 视图显示刷新时间或版本标识；运行中变化时提示“文件已更新，刷新以查看最新版本”。选择文件和滚动位置在切回聊天后保留。文件为空、没有差异、加载失败三者使用不同空态。

### 4.4 审批

需要批准时，任务显示“等待批准”，在会话中插入持久审批卡，工具条提供定位入口。卡片必须包含：待执行动作、目标路径或命令、工作目录、权限原因、相关运行标识，以及“允许本次”“拒绝”。默认焦点放在卡片标题或安全的中性位置，不默认聚焦允许，不通过 Enter 快捷键盲目批准。

一次批准只对应准确的一项待执行请求。请求被取消、已处理或过期后禁用按钮并标明结果；等待确认过程中禁用重复提交。只有后端明确支持且主方案定义其范围时，才增加“此会话允许”一类选项。审批完成后回显实际结果，不能先显示成功再等待服务器响应。

### 4.5 设置与连接

设置按“连接与模型”“外观”“工作区”“快捷键”“关于”分组，使用窗口内独立页面，保留返回原任务入口。首轮仅深色主题，不展示无法兑现的自动主题开关。

连接页按 Provider 列表管理，支持新增、编辑、删除和设置默认。表单包含自定义名称、API 形式（OpenAI / Anthropic）、OpenAI 的 Responses / Chat Completions 模式、Base URL 和 API Key；显示当前目标地址。模型支持获取列表和手动输入 ID，逐项区分未验证、文本可用、工具可用及失败。黑塔对话与编程执行默认共用模型，高级设置允许分别绑定 Provider 和模型。具体规则见 [Provider 规范](PROVIDERS.md)。连接表单只显示适配器真实支持的字段。凭证输入默认遮蔽；已有凭证不读取回明文；错误信息及日志不得回显凭证。提供测试连接及明确的成功/失败状态，模型发现失败允许重试。改动未保存时离开给出保存或放弃选项；不会把输入每个字符都当作有效配置。

## 5. 状态契约

以下是 UI 必须能够准确表达的状态，不代表已经实现的引擎枚举；实施时统一映射到主方案的运行协议。

| 状态 | 显示与可操作性 |
| --- | --- |
| 未连接/无配置 | 输入草稿可编辑；发送禁用并说明缺少的连接；提供设置入口 |
| 就绪 | 可发送；无伪进度；保留项目及模型上下文 |
| 启动中 | 显示“正在启动”；禁用重复发送；启动失败可重试 |
| 执行中 | 显示当前真实活动；停止按钮可用；可查看日志 |
| 等待批准 | 黄色图标及文本；持久审批卡；停止仍可用 |
| 正在停止 | 明确反馈已收到停止请求；禁止重复停止 |
| 已停止 | 保留已有输出和改动；说明停止不等于撤销文件变化 |
| 已完成 | 明确完成标记、摘要与变更入口；不声称未执行的测试通过 |
| 失败 | 人可理解的错误与可展开详情；重试、复制脱敏诊断入口 |
| 连接中断 | 保留已有内容；说明恢复状态未知时不能重复执行；只提供已支持的恢复方式 |

历史任务在应用重启后不能一律显示“执行中”：必须核验运行状态；主进程确认旧任务已经终止时标为“已中断”，尚未获得快照时标为“执行状态待确认”。加载骨架只用于真实读取；空态、失败态、无权限态不能合并。Toast 用于短反馈，审批和错误必须在持久区域可再次找到。

## 6. 键盘、辅助功能与动效

候选快捷键应在实施时检查系统及编辑器冲突，并允许在设置查看：Ctrl+N 新任务、Ctrl+O 打开项目、Ctrl+, 设置、Ctrl+Shift+E 切换项目导航、Ctrl+Shift+D 打开变更、Ctrl+L 聚焦输入。Escape 关闭最上层菜单/弹窗，不停止任务；停止任务使用明确按钮，避免误操作。

所有图标按钮有中文可访问名称；Tab 顺序遵循导航→工具条→主内容→输入→附加面板。弹窗锁定焦点、关闭后恢复触发点；菜单支持方向键。可调整分隔条提供角色、当前尺寸与方向键控制。状态播报使用低干扰 live region，不按每个流式 token 播报。高对比度模式下保留焦点和边界，屏幕阅读器可识别审批标题、目标和操作结果。

过渡时长 100–160 ms，仅用于菜单、折叠与悬停；遵循 `prefers-reduced-motion`。忙碌指示可以缓慢旋转，但在减少动效时改为静态图标加状态文本。第一轮没有打字机动画、全屏转场和自动音效。

## 7. 美术资产策略与清单

取得素材和把素材打包进公开仓库是不同动作。先记录来源、作者/出处、使用说明及是否可随项目分发；来源不明的角色图留在用户本地，不自动提交或作为下载脚本的默认资源。用户的个人非商用二创定位作为设计上下文，不作为第三方许可状态的证据。

| 资产 | MVP 必需 | 首选获得方式 | 未确认前的处理 |
| --- | --- | --- | --- |
| 大黑塔透明立绘 | 否 | 用户提供文件或指定出处；优先已有高清图 | 欢迎页不显示角色图，预留可关闭的右侧插画位 |
| 大黑塔头像 | 否 | 用户授权从所选立绘裁切或提供头像 | 使用文字“黑塔”或通用星形图标 |
| 应用图标 `.ico` / PNG | 是 | 自绘简约紫金几何星形，不直接冒用官方应用图标 | 用原创几何占位，并明确不是角色图 |
| 常规 UI 图标 | 是 | 复用已审计许可的上游图标库或开源单一图标库 | 统一 18/20 px，线宽一致 |
| 星象线条/魔女符号 | 否 | 少量本地 SVG 几何图形 | 最多欢迎页一处，透明度低，不能降低可读性 |
| 音效与角色语音 | 否，首轮排除 | 后续用户主动选择 | 默认无声音，也不自动抓取游戏语音 |

后续实施可在等待用户选择素材时独立完成无图 UI；不因素材缺失阻塞引擎和交互开发。在准备正式加入角色图的里程碑，只集中询问一次：①用户提供文件还是指定可用来源；②欢迎页全身/半身立绘或仅头像；③是否希望随公开仓库分发。未获得回答时保持无角色图版本。不要因泛泛“美术资源可以生成”而启动角色图生成，用户已强调尽量不直接生成。

为每个实际入库素材建立 `assets/ASSET_MANIFEST.md`，字段至少包含路径、名称、原始来源链接、作者/出处、取得日期、许可或用户使用约定、加工方式、是否可分发、备用替换。该文件仅在实施素材接入时创建，本轮不虚构资产来源。角色图使用本地文件并限制格式、尺寸和解码失败处理；不让不可信 SVG 直接以 HTML 注入。

## 8. 可执行验收与截图清单

实现者应提供真实运行截图和检查结果，不使用概念图代替运行证据。每轮提交在 1360 × 900、960 × 640 两种逻辑尺寸检查，并至少在 100%、150% Windows 缩放下验证；200% 检查设置、审批和输入不被裁切。

| 场景 | 通过条件 |
| --- | --- |
| 首次启动，无连接无项目 | 可找到打开项目及设置入口；无假记录；所有禁用操作解释原因 |
| 长项目名、长任务名、中文路径 | 可获取完整名称；不覆盖状态与按钮；路径复制准确 |
| 中文输入法与多行消息 | 组合输入回车不误发送；换行快捷键与设置一致；草稿不无故消失 |
| 流式回答与阅读历史 | 底部正常跟随；用户上滚后不被拉回；回到最新可用 |
| 工具执行和停止 | 显示真实事件；停止有中间态和结果；停止后已有改动仍可审阅 |
| 审批成功、拒绝、过期 | 无重复提交；每个结果可回看；旧审批不能授权新动作 |
| 文本、二进制、大文件 diff | 有准确文件标识；不支持的内容有说明；没有空白假成功 |
| 断线与重启恢复 | 保留消息；状态不确定时明确显示；不自动重复危险执行 |
| 设置保存失败与测试连接失败 | 不丢原配置；失败原因清楚；截图和日志无凭证 |
| 全键盘操作 | 能完成新任务、输入、打开 diff、拒绝审批、返回聊天；焦点始终可见 |
| 无角色素材启动 | 布局完整，不显示裂图、空白装饰占位或素材下载失败提示 |
| 降低动效和高对比度 | 状态仍可辨认、焦点清晰，关键内容不依赖动画或底色 |

截图至少覆盖：无图欢迎页、正常执行的聊天、等待审批、变更审阅、设置连接失败、紧凑窗口。结果记录明确区分“通过”“失败”“未验证”，未实现功能不计为通过。

## 9. 给 UI 实施者的完成定义

先做语义令牌、基础控件和布局，再接真实任务状态、审批与 diff，最后接可选素材。以最少组件覆盖主要行为，不为每个状态制作独立风格。每个里程碑提交时附：对应界面、真实数据来源、键盘检查、缩放检查、已知限制及下一轮最值得改进的三项。是否进入下一轮由验收缺口决定，不以固定轮数掩盖未完成项。
