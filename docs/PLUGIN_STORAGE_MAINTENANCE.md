# 插件安装资料维护

安装包、私有资料、生成文件、修改提案和制作草稿共享512 MiB逻辑字节预算。设置里的“插件空间”展示总量与分类占用；无法核验时显示未知/错误，不展示伪0。各库的小额度仍同时生效。

## 用户流程与范围

设置→插件→执行插件的“插件空间”下提供“检查可清理资料”。只读预览列出候选、逻辑大小、引用保护和阻断原因；所有项默认不选。用户勾选后点“确认删除N项”。旧归档明确提示删除后无法再从该归档恢复。没有自动清理、默认全选、后台扩选或自动重试。

| 类别 | 已实现范围 | 保留边界 |
| --- | --- | --- |
| 未引用包 | 根`plugins-v2/blobs/<64位hash>.json`，全部引用可确认且未被保护才列候选；损坏包明确标注 | 当前、三历史版本、安装备份、可解析保留归档及有效安装/回退预览引用均保留；未知引用不猜删 |
| 安装临时文件 | 精确匹配`index.json[.backup].tmp-<UUID>`、`index.json.recovery-<UUID>`及链接描述临时文件格式 | 未识别名称、异常身份、不完整硬链接集合保留；不能只按文件年龄删除 |
| 旧安装归档 | 整组`damaged-<UUID>`、单独损坏索引、不可变链接描述 | 用户逐项明确选择；组内不另挑孤儿，删除坏归档后须重新预览才能发现新孤儿 |
| 其他业务资料 | 不进入此次清理 | `plugin-data-v2`私有资料、`plugin-artifacts-v1`生成文件、`plugin-patches-v2`提案/原文/提交凭据不是缓存；仍保留 |

所有路径从主进程固定profile推导。渲染层仅收到名称、分类、数量、字节、ID和固定原因，不收到正文或profile绝对路径；确认不提交路径、引用集合或自行估算的大小。Guest没有清理或恢复能力。

## 引用与身份保护

安装库复用严格`parseIndex`，检查当前`index.json`、`index.json.backup`、单独损坏索引及整组保留归档的索引。启用和停用插件的当前/历史版本一律保护。有效安装/回退预览另纳入保护集合；预览集合改变也会使清理预览失效。

缺失备份、损坏/未知记录或无法完整解析的归档会阻断孤儿包类别，不将“无法读取”当作空引用，不通过正则捞几个hash后猜删。独立旧归档和精确temp若可完整核验，仍可供明确选择；删除它们不顺带授权删除组外blob。产物/提案的producer hash是来源说明，不是加载包的引用；其正文与凭据始终不进本批清理。

预览绑定安装hostRevision、有效安装预览签名、所有已检查文件的身份/元数据、引用正文和候选内容摘要、完整目录集合。确认前重新检查；连同正文未变但mtime变化也会失效并零删除。普通文件使用BigInt dev/ino等身份；目录和链接入口同样复核。未知/外部硬链接不列可删项；可完整确认的内部硬链接按路径逻辑字节计数，不称实际磁盘释放量。

检查限制为20000条目、深度8、单个需散列文件64MiB、总散列1GiB、保留解析文本32MiB，索引自身16MiB上限。超限或不能完整核验时保留并报告，不放宽检查。单次最多256个候选、最多4份预览、10分钟有效；更多资料需新的显式检查。

## 队列、业务屏障与确认

顺序是业务准入屏障→安装库serialized队列→同profile协调器队列→身份检查/删除。控制器排除正在启动/运行的插件、在途安装/文件选择、提案应用和另存请求；遇忙拒绝，不靠终止现有工作取得空闲。维护期间新相关操作不能进入，结束立即释放。没有在全局锁内等待用户确认、选择器、模型或命令。

安装库持有自身队列，避免新blob已写但索引尚未提交的间隙被误判孤儿。协调器维护入口不接受任意路径或任意写回调；普通`snapshot/withWrite`规则不变。确认开始前全部重新核对，任一变化零删除；开始删除后每个条目和祖先立即复核，归档从叶到根处理，链接只解除入口不跟随目标。

请求为：

- `maintenance-preview { hostRevision }` → `maintenancePreview`。
- `maintenance-confirm { previewId, selectedIds, hostRevision }` → `maintenanceResult`。
- `maintenance-discard { previewId }` → 丢弃宿主预览。

确认均一次消费；hostRevision改变、过期、页面卸载或迟到响应不能重用旧预览。失败/取消后必须重新检查，再由用户决定，不自动扩大删除集合。

## 超限且损坏链接时的零增长维护

固定`blobs`链接修复需要先保存描述并预留重建峰值；已超额时可能无空间执行。宿主提供`inspectMaintenance/prepareMaintenance/deleteConfirmedMaintenance`，使用同profile队列完成受限零增长删除：不新建临时目录、日志、receipt或备份，不提供“跳过统计后写入”的回调。

总量暂时无法统计时仍可核验已存在的独立旧安装归档、损坏索引/链接描述和精确temp。当前index/backup、活blobs入口及其他业务资料库不进入这种豁免删除；孤儿包仍要求引用完整、正常统计成功。所选归档内链接只绑定lstat/readlink身份、解除该入口，不访问目标，不把未知目标内容当0计入可释放空间。

已验证流程为：超限并含活blobs junction→预览/确认删除独立旧归档→普通写入和统计仍因链接受阻→用户另行显式重建→窄修复重新核算预算、保存不可变描述、解除链接并重建。外部目标不变。若安全候选不足以腾出修复所需空间，保留受保护资料并明确失败，不能自动扩大清理范围。

## 结果与失败语义

`deletedCount`是完整删除的已选候选数，整组归档删完才算1；`deletedBytes`是实际删除普通文件的核验逻辑字节。归档部分失败可能`deletedCount=0`而`deletedBytes>0`。`retainedCount`包含未完整删除的已选项，其中包括`failedCount`，两者不能相加当独立类别。`cancelled`与`issues`说明停止原因；未处理项保留。

后续取消、统计失败不能抹掉已删除事实。`usageKnown=false`明确总占用仍未知，绝不展示伪0或声称恢复普通写入。删除成功不等于可撤回；这是单宿主队列下的多步骤操作，不是多文件/断电事务、跨进程锁或OS级删除CAS。最后检查与系统调用之间的外部进程竞争仍存在，不新增多宿主保证。

## 私有资料恢复与制作草稿

私有资料损坏时，先查看当前记录和备份状态，再明确选择恢复有效备份或保留原件后重建。无法完整核验的链接/记录不可强盖；恢复预览会因版本或文件变化失效，不能把存储错误当成空资料。

制作草稿通过工坊自己的预览/确认删除，包括可核验ID的损坏稿；无法确认范围则禁删。此操作不卸载已安装插件，不删除聊天、项目、产物或提案。中途失败可能只完成部分删除，界面如实显示并要求重新检查。
