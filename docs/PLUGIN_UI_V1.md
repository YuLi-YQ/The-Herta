# 插件受控结果视图

这是数据型结果视图与声明动作接口，不是任意网页或组件注入。安装与基础能力见[插件开发说明](PLUGIN_SDK_V2.md)。

插件返回内容与可选的后续动作，应用负责渲染、输入表单、主题、焦点及实际权限。插件不能传 HTML、CSS、React、事件函数、URL、宿主路径或执行代码到界面。文本中的 HTML 和 URL 只作为文字展示。

## 创建与更新

动作需要在 manifest 和自己的 capabilities 中声明 `ui.present`，并得到安装授权。更新还要声明并获得 `ui.update`。所有调用都必须等待完成：

```js
const handle = await api.ui.present({
  view: {
    title: '文本检查',
    blocks: [{ type: 'status', tone: 'info', text: '正在统计。' }],
    actions: []
  }
});

const updated = await api.ui.update({
  viewId: handle.viewId,
  revision: handle.revision,
  view: {
    title: '文本检查',
    blocks: [{ type: 'fields', items: [{ label: '实际行数', value: '3' }] }],
    actions: []
  }
});
return '统计完成。';
```

示意代码的数字仅表示协议格式；实际插件应从输入计算。可导入的 [文本检查器](examples/plugins/text-inspector.herta-plugin.json)使用真实计算结果，不调用模型。

每次运行最多创建一个视图，首次返回宿主生成的 `viewId` 和从 1 开始的 `revision`。更新提交整份新内容，必须带当前 ID 和 revision；成功后返回递增版本。不能用旧版本覆盖新内容，不能更新另一运行的视图。多个更新要依序等待并使用上一次返回的版本。

进行中的内容可以显示，但后续动作只在运行成功结束后可用。失败、取消或归属失效后，视图和草稿提案会失效；插件自己展示的状态文字不能覆盖宿主的运行结果。

## 视图结构

定义为 `{ title, blocks, actions }`，只有这三个字段，ID/revision 不能由插件指定。title 为非空文字，最多 120 个 UTF-16 单位。最多 24 个内容块、8 个动作。完整视图 JSON 的 UTF-8 上限为 48 KiB，单项上限不是可以同时全部用满的保证。

| type | 字段 | 用途与限额 |
| --- | --- | --- |
| `text` | `text` | 普通文本，最多 8,000 单位，保留换行 |
| `code` | `code`, 可选 `language` | 只读代码，最多 16,000 单位；语言名最多 32 个受限字符，未知语言按纯文本显示 |
| `list` | `items: string[]` | 最多 100 项，每项 2,000 单位 |
| `table` | `columns: string[]`, `rows: string[][]` | 1–12 列、最多 100 行，每格 2,000 单位；每行必须与列数相同 |
| `status` | `tone`, `text` | tone 为 info/success/warning/error，正文最多 2,000 单位；宿主使用图形/文字及颜色表达 |
| `fields` | `items: {label,value}[]` | 最多 32 项只读标签/值，label120、value2000；交互参数使用 manifest 动作表单 |

空列表、空行集和空字段集合法，表格必须至少有一列。未知字段、未知块类型、重复按钮 ID、不安全对象键、非法控制字符和不成对的 UTF-16 surrogate 会被拒绝。TAB/LF/CR 可用于普通文本和代码。代码高亮由宿主固定组件处理，插件不能插入自己的高亮 HTML。

## 后续动作

视图中的每个按钮使用：

```json
{
  "id": "prepare-note",
  "label": "准备统计便笺",
  "actionId": "prepare",
  "inputJson": "{\"text\":\"用户可以修改的统计正文\"}"
}
```

- `id` 是视图内唯一 ID；`actionId` 必须是同一插件 manifest 中已经声明的动作，且适用于当前区域。二者均采用 manifest 的动作 ID 字符规则，最多 64 单位。
- label 是非空文字，最多 120 单位。`inputJson` 是 JSON **对象文本**，上限 32 KiB；按目标动作的实际参数定义验证并补入声明的默认值。不能夹带未知参数、授权或其他会话身份。
- 点击按钮先打开宿主生成的参数表单，预填这些值。用户可以检查和修改；点击“开始运行”才启动动作。不是插件在界面背后自动调用另一个动作。
- 选择及启动时再次核对原运行、视图 ID/版本、插件内容、当前会话和草稿修订。动作的声明与实际授权仍单独检查；按钮不授予新能力。聊天视图不能指向仅工作台的动作。
- 新运行实际被接受后，原视图的操作被消费，不能双击或重发成第二次运行。参数不合法、权限不够或尚未成功启动时保留原结果，允许修正；版本/会话已失效时需重新运行原动作。

后续动作是独立运行，使用自己的声明能力和预算。需要新视图时，应再次 `ui.present`，不能沿用前次运行的句柄。需要草稿时使用 `draft.append`，仍要由用户另点“追加到草稿”，不会直接发送。

## 使用与开发边界

视图属于当前运行结果，未作为永久聊天内容持久保存。关闭菜单或重启后不要依赖旧按钮；重要信息可明确加入草稿，或由插件使用自身有界资料存储。运行结果有保留数量/期限，不能把它当作长期文档数据库。

本接口支持数据型展示、受控更新和声明动作；不支持任意 DOM、远程页面、插件自带样式或 iframe。可编辑参数依 manifest 的 text/select/number/boolean 定义渲染。使用同一组主题与键盘规则，没有额外动画依赖。

文件提案、命令、网络及产物都是独立授权能力，受控视图不能授予它们。实际接口与预算见[SDK](PLUGIN_SDK_V2.md)，生成、试跑和明确安装流程见[插件工坊](PLUGIN_WORKSHOP.md)。界面展示成功不替代宿主记录的执行结果。
