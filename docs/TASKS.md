状态：2026-10-07第十五轮真实服务/重启恢复验收完成，产品仍为0.8.4，无新增代码或安装。报告见docs/reports/round-15.md；剩余边界见docs/PROGRESS.md。

本任务书配合 [实施主计划](IMPLEMENTATION_PLAN.md)、[视觉规范](DESIGN_SPEC.md) 和 [验收标准](ACCEPTANCE.md) 使用。发生范围冲突时先更新主计划，并在交付说明中记录决定。

## 给实施模型的总指令

1. 先阅读本地 `AGENTS.md`（如有）、上述文档和已存在的代码，再开始工作。不得假设上游已有某个类、事件或 IPC 名称。
2. 以上游 PersonaCLI/Herta 为复用基础。先确认实际许可证、依赖、启动链路、Windows 支持和现有 agent 实现；把事实与拟议设计分别记录。保留许可证和必要归属信息。
3. 保持真正的 Electron 桌面交付；开发服务器只能用于开发，不是最终交付。优先复用可运行功能，再替换界面和收敛架构，避免无依据的全面重写。
4. 默认只制作简约的大黑塔主题：深紫、黑金、克制的魔女与星象细节。优先上游或用户提供素材；没有确认的角色素材时使用无需角色插画的完整布局。不得直接生成角色美术或把待确认图片塞入发布包。
5. 每个任务都提交实际变更、验证结果和剩余问题。未执行的测试写“未执行”，受账号或设备限制的测试写“阻塞”，不能写“通过”。不得用 mock 成功代替真实 API 或安装包成功。
6. 默认不替用户提交、推送或发布。用户每轮审阅并自行上传项目；下一轮从用户提供的仓库状态和反馈继续。

## 并行协作规则与文件所有权

以下是职责边界，不宣称仓库已经存在对应路径。第一轮完成仓库地图后，协调者须把逻辑区域映射到实际路径并记入 `docs/OWNERSHIP.md`。新增文件路径由协调者确定后再下发。

| 角色 | 独占修改范围 | 交付责任 |
| --- | --- | --- |
| 协调者 | 根目录依赖清单与锁文件、构建配置、主计划、公共契约及集成记录 | 确定基线、安排依赖、合并与最终验证 |
| 桌面代理 | Electron 主进程、preload、系统集成、凭据存储、打包配置中被明确分配的文件 | 可信边界、原生窗口、运行生命周期 |
| 界面代理 | renderer 组件、样式、主题与已批准静态素材 | 布局、交互、无障碍和视觉回归 |
| 会话代理 | agent 适配、会话与消息数据、工具执行协调中被明确分配的文件 | 真实调用、状态迁移、恢复与取消 |
| 验证代理 | 独立测试、验收证据与缺陷记录 | 跨层验收、复现与回归；不顺手改其他代理负责的产品文件 |

只有四个并发名额时，协调者保留一个，其余按阶段选三个职责；验证角色在实现代理结束后启动。主进程与会话代理共享边界时，先由协调者明确契约和文件归属，再并行。未经协调不同时修改同一文件，不由多个代理更新锁文件。每个代理完成后报告文件清单，协调者检查差异再集成。公共契约改变必须先通知所有消费者。

## 第一轮：导入上游并建立可运行基线

交付目标：在 Windows 上能够启动桌面程序并生成最小可运行安装包，明确哪些能力可以复用、哪些需要补足。本轮不承诺完成重设计。

### R1-01 上游与许可证核验（协调者）

- 依赖：无。
- 输入：上游地址、当前工作区、本任务书。
- 所有权：基线导入和根目录配置，仅协调者写入。
- 工作：检查当前 Git 状态，保留已有用户文件；确认上游分支与 commit，核查许可证及第三方素材许可；选择可追溯导入方式，禁止把另一仓库的 `.git` 覆盖进当前目录。记录所需运行时、包管理器及 Windows 限制。
- 固定基线：上游 commit `8fb809934e0807ee0f0f590d87365a83bb720ca2`；更换版本须说明原因并重做差异审查。
- 输出：上游 commit、导入方法、许可证清单、安装与启动步骤、无法复用的部分及依据。
- 验证：对照上游文件结构与许可证；执行原有安装/启动命令并保存结果，依赖失败先定位原因。
- 完成定义：可以定位导入来源，用户文件未丢失，后续模型知道用哪个版本继续。

### R1-02 仓库地图和最小契约（协调者 + 各职责只读审查）

- 依赖：R1-01。
- 输入：真实源码及上游运行结果。
- 所有权：协调者拥有仓库地图、公共契约与 `docs/OWNERSHIP.md`。
- 工作：定位主进程、preload、renderer、agent、持久化、工具执行、凭据、打包入口；逐项标注“已存在/需调整/需新增”。定义最小会话事件和取消、审批、错误的语义，优先适配现有接口，不凭计划预设 SDK。
- 输出：实际路径映射、事件/状态表、模块调用方向、agent 支持矩阵及本轮缺口；列出 DeepSeek 专用配置、密钥门槛、模型枚举和 persona completion 耦合点；冻结 PROVIDERS.md 的配置、能力及协议边界，由协调者唯一维护公共契约。
- 验证：每条关键路径引用实际代码；检查是否存在 renderer 直接接触密钥或任意 shell 的路径。
- 完成定义：代理可依据真实文件分工；所有跨层修改有唯一所有者。

### R1-03 桌面基线与素材清单（桌面代理；界面代理独立盘点素材）

- 依赖：R1-02；两者可在不同文件并行。
- 输入：映射后的源码、视觉规范、上游素材。
- 所有权：桌面代理只修必需启动问题；界面代理仅写素材清单与来源记录。
- 工作：启动 Electron 窗口并记录功能基线；清点图标、字体、角色图及其来源。对缺失素材提出具体需求，如透明半身图、构图方向、允许裁切区域，不自行生成。
- 桌面与打包必做：设置本项目独立 `appId` 和 `userData`，禁用上游自动更新通道。上游 GUI 分发要求缺失的 voice/TTS 资源时，提供明确的无语音构建模式，隐藏或禁用对应入口，继续保留第三方 notices 校验，不能靠跳过全部校验完成打包。
- 输出：桌面启动证据、复用/替换清单、资产路径和来源表、最多三项必要用户选择。
- 验证：桌面窗口可关闭重开；最小安装包可脱离开发服务器启动；检查应用数据目录独立且不会请求上游更新；记录基线测试结果和已知缺陷。
- 完成定义：最小 exe 可运行，基线问题与新需求可区分，第二轮不必猜测素材或架构。

## 第二轮：简约大黑塔桌面界面

交付目标：完整可操作的桌面外壳，形成可供用户审美反馈的界面。若真实 agent 尚未连接，必须显著标注演示数据。

### R2-00 正式名称 The Herta（协调者分配给桌面与界面代理）

- 依赖：第一轮报告；不要求本次重新审查第一轮实现。
- 所有权：桌面代理负责应用显示名、安装配置与新产物命名；界面代理负责窗口内品牌、关于和欢迎页；协调者负责文档及公共元数据。开始前按实际 OWNERSHIP 分配到文件，避免并行冲突。
- 工作：统一为 `The Herta`，新产物可用 `The-Herta` 文件名前缀；保留上游归属和历史报告原名。默认保持第一轮 appId `personal.herta.atelier` 与 `%APPDATA%/HertaAtelier` 稳定，显示名称与内部标识解耦；如确需更换内部标识，另做可回退的数据/凭据迁移，不凭字符串全局替换改变存储位置。
- 输出：改名范围、保留旧标识的原因、窗口/关于/新安装包展示证据。
- 验证：新名称显示一致，旧会话和配置仍可读取；已有产物与历史哈希不改写；相关品牌测试更新预期，不删除测试。
- 完成定义：新界面与新产物使用 The Herta，品牌变化不会造成数据丢失或写入上游目录。

### R2-01 设计令牌和窗口骨架（界面代理）

- 依赖：第一轮通过；参考 DESIGN_SPEC.md。
- 输入：上游界面结构、窗口约束、确认后的素材。
- 所有权：主题、布局组件、批准素材；根构建配置由协调者处理。
- 工作：建立颜色、字号、间距、圆角及交互状态令牌；实现会话侧栏、主对话、输入区、可收起的工具/变更详情。核心操作有清晰标签；金色和星象细节克制，不让装饰遮挡正文。
- 输出：可运行桌面 UI，空态/加载/错误/长对话/窄窗口状态，必要截图；Provider 增删改、协议选择、Base URL/凭据表单、模型获取与手填、验证状态，以及对话/执行模型绑定界面。功能尚未接线时明确标记。
- 验证：常见 Windows 缩放、长中文、键盘操作、正文对比度和输入焦点；使用真实窗口而非仅浏览器截图。
- 完成定义：布局无明显溢出，主要操作可发现，角色素材可缺省而不留空洞。

### R2-02 桌面交互与工作区（桌面代理）

- 依赖：R1-02；与 R2-01 按契约并行。
- 输入：实际 IPC 边界、Windows 窗口需求。
- 所有权：主进程与 preload 的分配路径。
- 工作：落实窗口关闭/最小化/最大化、原生文件夹选择、可信工作区路径、外链策略及窄化 IPC；复用原生标题栏或明确实现拖拽与按钮热区。
- 输出：真实桌面操作通路和输入校验。
- 验证：中文带空格路径；取消文件夹选择；拖拽热区不吞按钮；renderer 无不必要系统权限。
- 完成定义：界面中呈现的桌面操作都能执行，未实现入口不得伪装可用。

### R2-03 状态样例与视觉验收（验证代理；实现代理完成后）

- 依赖：R2-01、R2-02 集成。
- 输入：实际桌面构建和设计规范。
- 所有权：测试、截图、缺陷单。
- 工作：用明确标记的可重复数据覆盖审批卡、工具输出、失败重试和长消息。标注哪些只是展示，哪些已接真实后端。
- 输出：视觉验收表、用户审阅截图、可复现缺陷与修复优先级。
- 验证：按 ACCEPTANCE.md 的界面项执行。
- 完成定义：阻断交互的缺陷修复；用户可据完整界面反馈，素材需求已具体化。

## 第三轮：真实 agent 完整流程

第三轮历史执行入口为 [ROUND_3_BRIEF.md](ROUND_3_BRIEF.md)，状态见 [PROGRESS.md](PROGRESS.md)。第二轮已交付，原生验收欠项保留到第四轮补验。R3-01 细分为协议、角色与真实会话接线，R3-02 增加旧配置/凭据迁移；按启动说明的顺序和实际文件所有权执行，不重新导入或复查前两轮。

交付目标：完成 PROVIDERS.md 定义的 OpenAI Responses、OpenAI Chat Completions、Anthropic Messages 三个协议模式；支持自定义 Provider、Base URL、API Key 和模型，分别验证从角色对话到工具执行、审批、变更查看和会话恢复的完整流程。

### R3-01 真实服务与会话状态（会话代理）

- 依赖：第一轮服务支持矩阵、第二轮界面契约。
- 输入：上游实际 SDK/API 能力及可用的用户配置；不在仓库内保存凭据。
- 所有权：会话、流事件适配、消息持久化的分配路径。
- 工作：按 PROVIDERS.md 接入三个协议模式、统一流事件和工具调用；实现模型发现/手填、能力验证、Provider 持久化和旧 DeepSeek 配置迁移；重构角色上下文，去掉 DeepSeek completion 必需依赖。黑塔和执行器支持独立绑定 Provider + model，默认共用。记录配置方式。区分连接中、输出中、待审批、工具执行、取消、成功和失败；保留调用关联关系，防止多会话事件串线。定义重启后未完成会话的恢复策略，不能自动重跑有副作用的工具。
- 输出：真实流式对话、可恢复历史、清晰的失败和取消状态。
- 验证：每个协议模式至少一条真实 API 完整会话，至少一个自定义非默认 Base URL；仅配置 OpenAI 或仅配置 Anthropic 均可独立运行；验证混合角色绑定、模型列表失败后手填与不支持工具的模型；断流、超时、重复事件、多会话切换、进程重启；确定性异常用 mock 单独覆盖。
- 完成定义：真实与 mock 证据分开，失败不会显示成功，重启不重复执行工具。

### R3-02 工具、审批与凭据（桌面代理）

- 依赖：R3-01 契约冻结；可并行实现内部逻辑。
- 输入：实际工具实现、工作区边界和上游授权机制。
- 所有权：工具执行、审批信任边界、凭据存储的分配路径。
- 工作：明确命令/文件操作的审批范围；主进程验证实际执行参数和工作区，不把 renderer 的批准布尔值当作充分授权。拒绝、取消、过期审批不可执行；关联审批与具体操作。凭据通过 Windows 可用安全存储保护，失败时明确提示，不能悄悄落明文；日志脱敏。
- 输出：真实工具流程、有效取消、凭据增删和安全错误处理。
- 验证：审批批准与拒绝、待审批时取消、执行中取消及子进程、路径越界/中文路径、密钥不出现在日志与 renderer 状态。
- 完成定义：可证明拒绝后无副作用；取消后状态一致；已知边界以可理解文案呈现。

### R3-03 工具与变更交互（界面代理）

- 依赖：R3-01/R3-02 契约；不能用自造事件替代真实接线。
- 输入：真实工具事件、文件差异与审批内容。
- 所有权：工具卡、审批交互、变更浏览与会话 UI。
- 工作：显示用户需要判断的命令、目标路径和差异；长输出可折叠；区分成功、失败、拒绝、取消；禁用失效操作，显示可执行的恢复入口。
- 输出：真实事件驱动的操作界面。
- 验证：审批前后一致性；跨会话切换；巨大输出下输入仍可用；差异显示与磁盘内容核对。
- 完成定义：无演示数据混入真实会话，用户可理解 agent 做了什么、在哪里失败。

### R3-04 完整流程验证（验证代理）

- 依赖：前三项集成。
- 输入：固定测试工作区、真实账号配置、异常模拟能力。
- 所有权：验收证据和缺陷记录。
- 工作：按 ACCEPTANCE.md 跑成功、拒绝、取消、断流、恢复流程；出现阻断缺陷退回对应所有者。
- 输出：按用例列出的证据、真实 API 消耗说明、未覆盖项。
- 完成定义：核心流程通过；不能实测的 API 路径明确阻塞，不提前宣称本轮完成。

### R4-01 Windows 安装与分发（桌面代理 + 协调者）

- 依赖：第三轮通过。
